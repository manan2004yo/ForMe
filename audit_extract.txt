I. BACKEND AUDIT

There is no custom backend server. This section covers the Firebase backend.

I1. Firestore Security Rules

AGENTS.md states: "Do not modify Firebase Security Rules through code â€” do it in the Firebase Console." The DEPLOYMENT.md states Firestore should be in "test mode" for development.

Test mode Firestore rules allow any authenticated user to read/write any document. This means:

Any logged-in user can read any other user's food logs, weight history, workout data
No server-side authorization enforces that uid in the document path matches the authenticated user

This is a critical security issue. It's documented as intentional for development but must be fixed before production.

I2. No Server-Side Validation

All caloric calculations, macro calculations, and profile validation happen client-side. A malicious user could write arbitrary data directly to Firestore.

I3. No Rate Limiting

Firebase has built-in rate limiting but no custom rules or Cloud Functions enforce application-level rate limits.
