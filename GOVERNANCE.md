- consequential actions
- system-of-record state

- perception
- interpretation
- estimation
- reasoning

Consequential actions require deterministic safeguards.

- conservative
- context-aware

- Recipes, batch meals and leftovers
- AI nutrition estimates with explicit uncertainty

Stage C — SNAP
Target flow: camera → perception → estimate → uncertainty → user confirmation → deterministic persistence
SNAP must never turn an AI perception or estimate into a verified fact without appropriate confirmation or authoritative evidence.

Stage D — RECOVERY
- Build contextual readiness from appropriate signals
- Use baseline and timing appropriately
- Handle subjective/objective conflicts
- Never equate HRV directly with CNS or recovery truth
- Prevent multi-source double counting
- Respect wearable and integration limitations

Stage E — VYBE Operator
VYBE becomes the fitness-domain operator and natural interaction layer, not a generic chatbot.
Ideal lifecycle: voice → STT → intent/entities → FORME Context Engine → deterministic action or AI reasoning → confirmation when needed → actual action → persistence → feedback
- VYBE can say "I don't know."
- AI remains provider-neutral and replaceable.
- AI does not directly perform arbitrary database writes.
- Consequential actions remain under deterministic FORME control.

Stage F — System Integration
Connect TODAY + FUEL + TRAIN + RECOVERY + PROGRESS + VYBE into one longitudinal system.
Desired experience: context → understanding → interaction → response → next action

Stage G — Longitudinal Learning
- Recognize useful patterns without pretending certainty
- Prefer "you usually..." over "you always..."
- Make learned patterns explainable and correctable
- Connect goals, actions, data, history and next decisions
